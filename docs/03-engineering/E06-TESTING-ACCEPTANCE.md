## 1. 测试目标

测试不是为了“覆盖率好看”，而是为了证明：

1. 配方图、单位换算、库存余额、计划快照在边界条件下仍然正确。
2. 数据库事务在并发、进程死亡、磁盘满时不会留下半条数据。
3. 备份/恢复/迁移失败时，现有数据不被破坏。
4. 无网络时核心流程完整可用。
5. 模块边界没有被测试“绕过”（例如 UI 测试直接写 DB）。

**“应用能打开”不是完成标准。**

## 2. 测试分层

```text
                 ┌─────────────────────┐
                 │ 手工验收 / 真机 E2E  │  少、慢、覆盖真实设备
                 ├─────────────────────┤
                 │ Compose UI 测试      │  关键屏幕与状态
                 ├─────────────────────┤
                 │ 集成测试（真 SQLite）│  事务、约束、迁移、备份
                 ├─────────────────────┤
                 │ 单元测试（JVM）      │  领域规则、映射、状态机
                 └─────────────────────┘
```

| 层 | 工具 | 运行环境 | 目标 |
|---|---|---|---|
| 单元 | JUnit4 + Truth + MockK | JVM | 快、稳定、覆盖规则 |
| 协程 | coroutines-test + Turbine | JVM | 虚拟时间、Flow |
| 数据库 | Room in-memory / Robolectric | JVM/Android | DAO、约束、事务 |
| 迁移 | Room `MigrationTestHelper` | Android/Robolectric | 每个 schema 版本 |
| UI | Compose UI Test | Android/Robolectric | 关键屏幕、无图状态 |
| 集成 | 真 SQLite + 临时文件 | Android | 仓储/备份/文件 |
| E2E | 手工清单 + instrumented | 真机/模拟器 | 真实流程 |
| 性能 | Macrobenchmark/计时 | 真机 | 启动/查询/展开 |

## 3. 测试命名与结构

```kotlin
class RecipeGraphValidatorTest {
    @Test
    fun `rejects self reference with full path`() { ... }

    @Test
    fun `rejects cross type cycle recipe to sauce to recipe`() { ... }
}
```

- 测试名描述行为，不写实现。
- 一个测试一个断言主题；避免“大杂烩”。
- Given/When/Then 用空行分隔。
- 测试数据用 `TestData` 构造器，固定 `Clock`/`IdGenerator`。
- 不依赖真实时间、随机顺序、网络、设备语言。

## 4. 单元测试重点

### 4.1 领域规则

| 对象 | 必须覆盖 |
|---|---|
| `UnitConverter` | 同维度、跨维度、COUNT 不互转、反向因子、近似标记、零/负数量、精度 |
| `RecipeGraphValidator` | 自引用、直接环、间接环、跨类型环、深度上限、节点上限、子版本未发布 |
| `RecipeExploder` | 线性缩放、子配方产量换算、重复物料、可选行、不可换算、空配方 |
| `RequirementAggregator` | 同单位合并、可换算合并、不可换算分行、可选不计缺口、商品缺失 |
| `InventoryAllocator` | FEFO、预留不超过在手、跨批次、部分满足、过期排除 |
| `PlanSnapshotPolicy` | 版本固定、旧计划不变、刷新新 revision |
| `PurchaseOrderStateMachine` | 部分收货、超收拒绝、取消、作废 |
| `BackupManifestValidator` | 必填字段、版本、hash、路径穿越 |
| `ErrorMapper` | SQLite/文件/权限 → 错误码 |

### 4.2 覆盖目标

- 领域规则：**分支覆盖 ≥ 90%**；关键不变量 100%。
- 数据映射：≥ 80%。
- 整体行覆盖不作为唯一指标；不为了覆盖率写无断言测试。
- 每个 P0/P1 缺陷修复必须加回归测试。

## 5. 数据库测试

### 5.1 必测约束

| 约束 | 测试 |
|---|---|
| 外键开启 | 删除被引用食材/商品失败 |
| 库存非负 | 扣减超过在手失败 |
| 预留 ≤ 在手 | 预留超过可用失败 |
| 条码唯一 | 重复条码失败 |
| 主条码唯一 | 同一商品第二个主条码失败 |
| 版本唯一 | 同实体重复 version_no 失败 |
| 当前版本唯一 | 两个 `is_current=1` 失败 |
| 流水只追加 | UPDATE/DELETE 流水失败 |
| 组成行三选一 | 类型与引用不匹配失败 |
| 账实一致 | 余额变化必有流水 |

### 5.2 事务测试

- 计划确认中途抛异常 → 计划仍 Draft，无快照/需求/预留残留。
- 收货过账中途失败 → 无批次/流水，采购数量不变。
- 库存调整失败 → 余额与流水都不变。
- 嵌套事务/重试不产生重复流水。

### 5.3 迁移测试

- 每个相邻版本迁移。
- v1 → 当前一次打开。
- 空库 vs 有数据。
- 大数据量（1 万行）耗时。
- 迁移失败回滚 + 预迁移备份恢复。
- 已发布版本内容 hash 不变。
- 旧快照仍可读。

## 6. 必测业务场景

以下 12 个场景来自任务书，必须有自动化或明确手工步骤与证据。

| # | 场景 | 操作 | 期望 |
|---|---|---|---|
| 1 | 菜谱引用自身 | 菜谱 A 的组成行引用 A，发布 | 拒绝，`CUL-REP-001`，路径包含 A |
| 2 | 多层循环 | A→B→C→A，发布/确认 | 拒绝，显示完整路径 |
| 3 | 多菜谱引用相同物料 | 计划含 A、B，均需黄油 | 需求合并为一行；来源两条 |
| 4 | 单位无法换算 | 1 杯面粉 + 库存按 g，无密度 | 保留杯单位并标记；不猜 120g |
| 5 | 商品被删除但有库存 | 归档/尝试删除有库存商品 | 禁止硬删；库存/流水保留；新计划不可选 |
| 6 | 计划执行期间配方被修改 | 确认计划后发布新配方版本 | 旧计划需求不变；新计划用新版本 |
| 7 | 同时多个库存写入 | 20 协程同时调整/出库 | 串行；余额=初始+Σdelta；无负库存 |
| 8 | 写入中途强杀应用 | 事务提交前 `am force-stop` | 重启后无半条流水；DB 一致 |
| 9 | 备份文件损坏 | 改一个字节/截断 | 预检失败；现有数据不变 |
| 10 | 导入过程异常 | 恢复中注入异常/磁盘满 | 回滚到恢复前；现有数据不变 |
| 11 | 图片文件不存在但档案存在 | 删除图片文件，打开档案 | 档案正常；按无图显示；记录 `CUL-FILE-002` |
| 12 | 数据库升级失败 | 注入错误迁移 | 回滚 + 恢复预迁移备份；不丢数据 |

### 6.1 补充场景

| 场景 | 期望 |
|---|---|
| 部分到货 | 多次收货累加；状态 `PARTIALLY_RECEIVED` → `RECEIVED` |
| 超收 | 默认拒绝；允许时记录原因 |
| 收货作废 | 未动用批次可冲正；已动用拒绝 |
| 预留释放/消耗 | 可用量恢复/在手扣减正确 |
| 计划无日期 | 可确认 |
| 计划无明细 | 拒绝 |
| 同一计划重复确认 | 拒绝 |
| 可选配料 | 不计缺口，单独显示 |
| 条码重复 | 冲突提示，不覆盖 |
| 无网扫码 | 本地识别成功 |
| 相机权限拒绝 | 可手工输入 |
| 中文搜索 | 名称/别名可搜到 |
| 时区/日期 | 计划日期按本地日期保存 |
| 图片全部删除 | 图片区域隐藏，无空占位 |
| 低存储 | 写入/备份失败有明确提示，不产生半文件 |
| 进程死亡后恢复 | journal 回滚/完成，数据一致 |

## 7. UI 测试

### 7.1 关键屏幕

- 食材列表/编辑/详情。
- 菜谱组成编辑（添加食材/酱汁/菜谱）。
- 计划确认（缺口摘要）。
- 库存批次/流水。
- 采购收货。
- 备份/恢复。
- 错误/空/无图状态。

### 7.2 必测状态

| 状态 | 检查 |
|---|---|
| Loading | 有明确进度，不闪烁 |
| Empty | 有空状态文案与主操作 |
| Error | 错误码、原因、恢复动作 |
| No image | 图片区域不存在（不是空框） |
| Only primary | 只显示主图 |
| With process images | 显示过程图区域 |
| Deleted all images | 区域隐藏 |
| Permission denied | 设置/手工输入入口 |
| Saving | 按钮禁用/进度，防重复提交 |
| Offline | 无网络提示不阻塞核心操作 |

### 7.3 UI 测试规则

- 不直接访问数据库；用 fake Use Case/Repository。
- 使用语义标签（`contentDescription`/`testTag`），不依赖文本位置。
- 不断言像素级布局；断言可见性与交互。
- 截图测试可选，不作为唯一验收。

## 8. 集成/E2E 测试

### 8.1 真实环境

- 真 SQLite（非 in-memory）以覆盖 WAL/文件/迁移。
- 临时目录管理图片。
- 使用真实 `TransactionRunner` 与写锁。

### 8.2 端到端流程

1. 新建食材“黄油”。
2. 新建商品“Président 200g”，绑定条码，库存 2 包。
3. 新建酱汁/菜谱，引用食材/酱汁/其他菜谱。
4. 新建计划，含两道菜，确认。
5. 查看需求合并、缺口、预留。
6. 生成采购单，部分收货，入库批次。
7. 再次收货，库存/流水正确。
8. 制作出库，预留消耗。
9. 备份 → 修改数据 → 恢复 → 校验回到备份时点。
10. 飞行模式重复核心步骤。

### 8.3 真机测试

- 至少一台真实 Android 手机（O-23）。
- 覆盖：相机扫码、SAF、后台备份、进程死亡、存储权限、厂商 ROM 差异。
- 模拟器不能替代扫码/SAF/后台限制的真实验证。

## 9. 离线与网络测试

- 飞行模式：创建/编辑/计划/库存/采购/扫码/备份全部可用。
- 无 Wi-Fi/移动数据：不出现网络错误阻塞。
- 若未来加在线查询：断网时自动降级本地，不弹致命错误。
- v1 不申请 `INTERNET` 权限；用 `aapt dump permissions` 验证。

## 10. 并发与故障注入

| 测试 | 方法 |
|---|---|
| 并发写 | 20 协程同时调整同一批次；断言余额/流水 |
| 并发预留 | 10 计划同时预留；断言不超卖 |
| BUSY 重试 | 注入 `SQLITE_BUSY` 两次；第三次成功 |
| 事务超时 | 注入慢 SQL；返回 Timeout，锁释放 |
| 进程死亡 | 测试钩子暂停在 commit 前，`adb shell am force-stop` |
| 数据库损坏 | 截断文件/写坏页；启动进入 Recovery |
| 磁盘满 | 限制临时目录/模拟 IOException |
| 迁移失败 | 注入错误 SQL；回滚 + 恢复 |
| 恢复中断 | 在 phase 间杀进程；journal 回滚 |

## 11. 性能测试

| 指标 | 目标 | 方法 |
|---|---|---|
| 冷启动到可交互 | ≤ 2.5 s（中端机） | Macrobenchmark/手工计时 |
| 档案列表首屏 | ≤ 300 ms | 基准测试 |
| 搜索 2 万条 | ≤ 200 ms | 生成数据 + 计时 |
| 配方展开 200 节点 | ≤ 500 ms | 单元/基准 |
| 计划确认 | ≤ 1.5 s | 集成测试 |
| 单条库存写入 | ≤ 100 ms | 集成测试 |
| 备份 100 MB | 后台完成，不 ANR | 手工/基准 |

性能不达标时，先查索引、N+1、主线程 I/O，不用“加载动画”掩盖。

## 12. 模块验收标准

### 12.1 食材

- [ ] 创建/编辑/归档；名称规范化唯一。
- [ ] 别名唯一；可按别名搜索。
- [ ] 食材级换算可增删；无依据时跨维度换算失败。
- [ ] 图片可选；无图不显示区域。
- [ ] UI 不直接访问 DB。

### 12.2 酱汁/菜谱

- [ ] 草稿可编辑；发布后不可变。
- [ ] 组成行支持食材/酱汁/菜谱。
- [ ] 循环检测覆盖自引用/多层/跨类型。
- [ ] 产量缩放正确；单位不兼容拒绝。
- [ ] 子配方未发布时拒绝发布。
- [ ] 旧版本仍可被旧计划引用。
- [ ] 版本历史可查看。

### 12.3 商品

- [ ] 商品必须关联食材。
- [ ] 一个食材多个商品。
- [ ] 包装内容量/库存单位/换算因子正确。
- [ ] 条码唯一；重复冲突。
- [ ] 有库存商品只能归档，不能硬删。
- [ ] 扫码/手工输入均可查到。

### 12.4 库存

- [ ] 批次、位置、到期日。
- [ ] 所有余额变化有流水。
- [ ] 预留/释放/消耗正确。
- [ ] 禁止负库存；并发不超卖。
- [ ] 流水不可改/删。
- [ ] 盘点/报损/调拨有原因与流水。

### 12.5 制作计划

- [ ] 多菜品、独立数量、日期可空。
- [ ] 确认时展开/合并/缺口。
- [ ] 确认后配方修改不影响旧计划。
- [ ] 刷新生成新快照，旧快照保留。
- [ ] 预留与实扣分离。
- [ ] 缺口可追溯到配方行。

### 12.6 采购

- [ ] 缺口生成采购需求。
- [ ] 采购单状态机正确。
- [ ] 部分到货累加。
- [ ] 超收默认拒绝。
- [ ] 过账创建批次 + 流水，原子。
- [ ] 取消/作废规则明确。

### 12.7 备份/恢复

- [ ] 备份包含 DB + 图片 + manifest + 校验。
- [ ] 自动/手动备份可用。
- [ ] 损坏备份拒绝，现有数据不变。
- [ ] 恢复前自动备份。
- [ ] 恢复失败可回滚。
- [ ] 旧 schema 恢复后迁移。
- [ ] 重复导入有提示。

### 12.8 设置/诊断

- [ ] 备份目录/加密设置。
- [ ] 诊断导出不含 DB/图片。
- [ ] 版本/schema/错误码可查看。
- [ ] 恢复模式入口可用。

## 13. CI 与测试矩阵

### 13.1 每次 PR

- ktlint、detekt、lint。
- 单元测试。
- Robolectric 数据库/迁移测试。
- `assembleDebug`。
- 依赖规则检查。

### 13.2 每晚

- instrumented 测试（API 33/36 模拟器）。
- 迁移全矩阵。
- 性能基准（可选）。

### 13.3 发布前

- 真机冒烟（扫码/SAF/后台/进程死亡）。
- 备份恢复演练。
- 离线全流程。
- 数据库升级演练（旧版本 → 新版本）。

### 13.4 设备矩阵

| 设备 | API | 用途 |
|---|---|---|
| 模拟器 | 26（需安装镜像） | 最低版本兼容 |
| 模拟器 | 33 | 常见旧设备 |
| 模拟器 | 35/36 | 当前主流 |
| 真机 | 用户实际设备 | 最终验收 |

> 当前环境只有 API 30/33/35/36.1 镜像，API 26 需补装或用 Robolectric 配置；真机尚未连接。见 R02/R03。

## 14. 缺陷分级与发布门禁

| 级别 | 定义 | 发布 |
|---|---|---|
| P0 | 数据丢失/损坏、隐私泄露、无法启动 | 阻止 |
| P1 | 核心流程不可用、库存错误、备份不可恢复 | 阻止 |
| P2 | 有绕过方案的功能缺陷 | 可带已知问题发布，需记录 |
| P3 | 文案/样式/低频问题 | 可发布 |

发布前必须：

- P0/P1 = 0。
- 必测场景全部通过或有明确豁免。
- 备份/恢复演练通过。
- 迁移测试通过。
- 真机冒烟通过。

## 15. 测试数据管理

- 所有测试数据用构造器生成，不依赖生产数据。
- 迁移测试使用固定 golden DB（提交到测试资源，脱敏）。
- 图片测试用小型生成文件，不提交大二进制。
- 时间/ID 注入，保证可重复。
- 测试结束清理临时目录/数据库。
- 不把用户真实数据放入测试。

## 16. 验收证据

每个模块交付时必须附：

- 测试清单与结果（通过/失败/豁免）。
- 关键场景截图/录屏（可选）。
- 迁移前后 schema 与数据校验。
- 性能数据（如涉及）。
- 已知问题列表。

没有证据的“已完成”不算完成。
