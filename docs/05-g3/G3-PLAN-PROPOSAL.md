# G3 实施计划（方案 A：数据安全优先）

**文档编号**：G3-PLAN-001
**版本**：`1.0.0`
**状态**：`Draft`（待项目负责人批准；批准前不修改业务代码、不建表、不调依赖、不建基线）
**日期**：2026-11-04
**方向依据**：项目负责人 2026-11-04 选择 **方案 A（数据安全优先）**
**基线**：`framework-0.1.0`（`2b523de`）

---

## 1. 目标

在 G2 基线上，先把"备份不一致、恢复不可用"的数据安全风险关闭，再补平台设备验证与业务模块；
每个阶段独立验收、打基线，不跨阶段抢跑。

**G3 完成定义（建议）**：

1. 备份在 WAL + 并发写场景下可证明一致（在线快照）；
2. 恢复可在 UI 发起，覆盖数据库与附件，失败可回滚，中断可恢复；
3. 扫码与 SAF 有设备级证据；
4. 至少配方模块端到端可用；
5. 远端 CI 实跑通过，产物归档，打 `g3-0.1.0`。

## 2. 阶段总览

| 阶段 | 名称 | 主要范围 | 依赖 |
|---|---|---|---|
| G3-0 | 门禁与规划收口 | 远端 CI、产物归档流程、G3 章程 | 负责人提供远端仓库/凭据 |
| G3-1 | 数据安全闭环 | 在线快照/checkpoint、附件恢复、活跃 WAL 验证、恢复 UI | G3-0 |
| G3-2 | 平台闭环 | 扫码/SAF 设备验证、最小 E2E | G3-1（恢复 UI 复用 SAF） |
| G3-3 | 食材与配方 | 食材增强；配方版本/组成/发布/循环校验 UI | G3-2 |
| G3-4 | 库存/计划/采购 | 库存流水、计划确认快照、需求汇总 UI、缺口/采购 | G3-3 |
| G3-5 | 质量与发布 | 全量门禁、性能、R8、发布检查、`g3-0.1.0` | G3-4 |

阶段内仍按"小步提交 + 每步测试 + 阶段报告 + 负责人验收"执行，沿用 G2 的验收协议。

## 3. 各阶段任务与退出条件

### G3-0 门禁与规划收口

**任务**

1. 项目负责人提供远端仓库与凭据；推送当前基线；实跑 `.github/workflows/ci.yml`；
2. 记录运行链接、提交 SHA、结果；
3. 建立构建产物归档流程（APK + mapping 存放到仓库外或 Release 附件）；
4. 确认 G3 章程（阶段划分、验收人、基线命名 `g3-stageN` / `g3-0.1.0`）。

**退出条件**

- [ ] 远端 CI 在 `2b523de` 或其后继提交上通过，有可访问记录；
- [ ] APK/mapping 归档位置确定并完成一次归档；
- [ ] G3 章程经负责人确认。

**阻塞**：远端仓库与凭据（唯一硬阻塞，未提供则本阶段无法完成）。

### G3-1 数据安全闭环（最高优先级）

**任务**

1. **在线快照**：实现 `DatabaseSnapshotter`（`core:data`）：
   - 写屏障：暂停新写事务（复用单写 Mutex / 事务协调器）；
   - `PRAGMA wal_checkpoint(TRUNCATE)`；
   - 复制主 DB 文件；
   - 释放屏障；失败必须回滚屏障并返回明确错误码；
   - 用 WAL 模式 + 并发写测试证明快照可打开且通过 `integrity_check`。
2. **附件恢复**：归档中的图片按 journal 逐文件安装；校验和失败即回滚；
   数据库与附件任一失败都回到恢复前状态。
3. **活跃 WAL 验证**：WAL 中仍有未 checkpoint 数据时执行恢复，确认无旧 WAL 污染。
4. **恢复 UI**：`feature:settings` 提供：
   - 选择备份文件（SAF）、预检结果（版本/PARTIAL/迁移）；
   - 恢复确认（含"覆盖当前数据"二次确认）；
   - 进度、失败原因、回滚结果；
   - 恢复完成后强制重建数据库连接（重启或重建实例）。

**退出条件**

- [ ] WAL + 并发写场景的在线快照测试通过；
- [ ] 附件恢复成功/失败回滚测试通过；
- [ ] 活跃 WAL 恢复测试通过；
- [ ] 模拟器上从设置页完成一次"备份 → 恢复 → 数据校验"；
- [ ] 中断恢复（进程被杀）在设备上可恢复现场。

**明确不做**：备份加密（除非负责人批准纳入）。

### G3-2 平台闭环

**任务**

1. 设置/调试入口接入扫码：相机权限三态、拒绝后手工输入；
2. SAF 导出/导入真实设备验证；
3. 最小自动化 E2E：
   - 食材新建→列表→重启；
   - 恢复流程（可用 Robolectric/仪器化组合）。

**退出条件**

- [ ] 模拟器或真机扫码成功或走手工兜底，有截图/日志；
- [ ] SAF 选择/写入设备验证通过；
- [ ] 两条 E2E 在 CI 或本地脚本中可重复执行。

### G3-3 食材与配方

**范围（建议）**

- 食材：别名、食材级单位换算、详情页；
- 配方：版本、组成行（食材/子配方）、发布、循环校验 UI、子配方展开预览。

**退出条件**

- [ ] 配方纵向切片端到端可用（新建→组成→校验→发布）；
- [ ] 循环引用在 UI 上被拒绝并显示路径；
- [ ] 子配方展开结果与领域算法一致。

### G3-4 库存/计划/采购

**范围（建议，需负责人确认）**

- 库存流水（入库/出库/调整）、商品与食材映射（U11）；
- 计划确认生成不可变快照（U10/U12 视范围）；
- 需求汇总接 UI、缺口计算与采购建议。

**退出条件**

- [ ] 计划确认 → 需求汇总 → 缺口展示闭环；
- [ ] 快照不可原地修改，刷新生成新快照；
- [ ] 库存写入串行、无负库存。

### G3-5 质量与发布

**任务**

1. 远端 CI 全绿；依赖规则、迁移、恢复演练、离线冒烟全部纳入；
2. 性能基线：200 节点展开、冷启动、DB 打开；
3. Release/R8、签名流程（如需发布）；
4. 打 `g3-0.1.0` 并归档产物。

**退出条件**

- [ ] 全部门禁在远端通过；
- [ ] 发布检查表完成；
- [ ] 基线标签与产物归档。
