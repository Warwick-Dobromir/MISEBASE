## 4. G3 目标候选

### 方案 A：数据安全优先（推荐）

先补 U06/U07/U09/U05，再补 U01/U02/U03/U04，最后进入业务模块。

- 优点：把"备份可能不一致、恢复不可用"这两个数据安全风险先消掉；符合离线优先定位；
- 代价：业务功能仍只有食材，产品可用性提升有限；
- 适合：把 CULINARY 当长期个人档案、不能接受丢数据的场景。

### 方案 B：业务优先

先做配方/库存/计划/采购的纵向切片，安全项后置。

- 优点：产品形态最快成形；
- 风险：在无一致快照、无恢复入口的情况下扩展业务，数据越多风险越大；
- 不建议作为第一阶段。

### 方案 C：发布优先

以"可发布 0.1"为目标，只做 U01/U13 + 最小业务（配方只读）。

- 优点：最快产出可安装版本；
- 风险：功能与数据安全都不完整，发布后返工成本高。

## 5. 建议的 G3 阶段划分（待批准，未创建基线）

| 阶段 | 名称 | 范围 | 退出条件（建议） |
|---|---|---|---|
| G3-0 | 门禁与规划 | 远端仓库/CI 实跑、APK 归档流程、G3 章程与基线规则 | CI 在远端通过并留记录；APK/mapping 归档 |
| G3-1 | 数据安全闭环 | U06/U07/U09：在线快照、附件恢复、活跃 WAL 验证、U05 恢复 UI | 备份→恢复演练在 WAL/附件场景通过；UI 可发起并回滚 |
| G3-2 | 平台闭环 | U02/U03/U04：扫码与 SAF 设备验证、最小 E2E | 模拟器/真机证据；E2E 覆盖两条关键路径 |
| G3-3 | 食材与配方 | 食材别名/换算/详情；配方版本、组成、发布、循环校验 UI | 配方纵向切片端到端可用 |
| G3-4 | 库存/计划/采购 | 库存流水、计划确认快照、需求汇总接 UI、缺口与采购建议（U10/U11/U12 视范围） | 计划→需求→缺口闭环 |
| G3-5 | 质量与发布 | 全量门禁、性能、R8、发布检查、基线 `g3-0.1.0` | 全绿 + 发布检查表 |

> 阶段 3–5 的具体切分需先确认业务范围；本表只是建议，不是承诺。
