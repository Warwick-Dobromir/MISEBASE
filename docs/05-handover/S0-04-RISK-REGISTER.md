## 1. 风险等级与状态

| 等级 | 含义 |
|---|---|
| **高** | 可能造成数据丢失、不可恢复损坏、核心流程不可用 |
| **中** | 可能造成功能错误、回归、维护成本上升 |
| **低** | 影响局部、可绕过、发布前处理即可 |

| 状态 | 含义 |
|---|---|
| `OPEN` | 风险存在，未缓解或未验证 |
| `PARTIAL` | 有部分代码/测试，但未覆盖关键场景 |
| `MITIGATED` | 有实现 + 可复现验证 |
| `MONITORED` | 当前无暴露，但需持续观察 |
| `CLOSED` | 已消除或不适用 |

### 1.1 本登记册的权限边界

**风险登记册不等于代码修改授权。**

- **MB-D-007 未签收前**：不得修改 `AutoBackupWorker` 的返回逻辑，不得修改 `BackupArchiveWriter`、`RestoreExecutor`、数据库写入屏障、WAL checkpoint 或其他备份/恢复行为；只允许补充测试、分析现有实现、编写修复方案与验证方案。
- **Stage 0**：不执行任何数据库修改。
- **Stage 1（获得授权后）**：可以准备迁移规范、测试模板、备份与回滚验证方案；**不得创建正式 Schema v2**，不得删除、迁移或结构性改造 11 张休眠表；任何 Schema 变更需 MB-D-005 签收并另立正式任务。
- 本册中的“防范措施/建议”是工程建议，不是已批准的实施指令。

## 2. 风险清单

### S0-R-01 数据库迁移破坏

| 项 | 内容 |
|---|---|
| **发生条件** | schema v2+ 迁移 SQL 错误；使用 `fallbackToDestructiveMigration`；迁移前无备份；旧数据违反新约束 |
| **影响范围** | 用户数据库、全部业务数据；可能导致无法启动 |
| **当前状态** | **PARTIAL**：v1 无迁移；无 destructive；但无 v2 迁移、无迁移前自动备份、迁移测试仅 2 例且本次未跑 |
| **防范措施** | 每个 schema 变更新增 `Migration(n,n+1)`；`exportSchema=true`；迁移前备份并校验；迁移后 `foreign_key_check` + `quick_check`；禁止 destructive；旧版本拒绝打开新 DB。**Stage 0 不执行；Stage 1 只准备规范/模板/测试，不创建 v2。** |
| **验证方法** | `MigrationTestHelper` v1→vN、相邻版本、空库/真实旧数据；迁移失败回滚演练；降级拒绝测试；模板验证不等于已实施迁移 |

### S0-R-02 WAL 与备份一致性

| 项 | 内容 |
|---|---|
| **发生条件** | WAL 模式下有并发写；备份直接复制 `.db` 文件；未执行 `wal_checkpoint(TRUNCATE)`；备份期间进程被杀 |
| **影响范围** | 备份缺少已提交事务；恢复后数据回退；用户误以为备份完整 |
| **当前状态** | **OPEN（高）**：`BackupArchiveWriter` 只读数据库文件；无 checkpoint；`AutoBackupWorker` 未实现编排；恢复测试使用 `TRUNCATE` journal mode |
| **防范措施（MB-D-007 签收后）** | 备份获取写锁/`WriteGate` → `wal_checkpoint(TRUNCATE)` → 复制/校验 → 释放；备份前 `quick_check`；备份后校验哈希；不在事务中做文件复制。**签收前仅分析/测试/方案。** |
| **验证方法** | 并发写 + 备份测试；活跃 WAL 恢复测试；进程中断测试；备份文件与 DB 逻辑一致性断言 |

### S0-R-03 多模块循环依赖

| 项 | 内容 |
|---|---|
| **发生条件** | feature 之间直接 import；core:data/database 反向依赖；新增模块未纳入规则 |
| **影响范围** | 构建失败、架构边界失守、模块不可独立测试 |
| **当前状态** | **PARTIAL**：源码扫描 0 违规；15/43 声明边 PASS；但检查脚本硬编码、只查 build.gradle、不查 import |
| **防范措施** | 重写依赖检查：模块集配置化 + 源码 import 扫描 + 拓扑排序；CI 门禁；feature 间通过 domain 端口/app 编排 |
| **验证方法** | `check-module-deps` 违规注入测试；Gradle 依赖图；循环依赖构造测试 |

### S0-R-04 Gradle 构建死锁/任务依赖循环

| 项 | 内容 |
|---|---|
| **发生条件** | 约定插件任务依赖成环；configuration cache 与并行构建冲突；KSP/Hilt 任务顺序错误 |
| **影响范围** | 构建挂起/失败；CI 超时 |
| **当前状态** | **MONITORED**：两次独立构建成功（1m 1s / 1m 54s 历史），未观察到死锁；未做压力/并行矩阵 |
| **防范措施** | 统一约定插件；CI 使用 `--no-daemon`；固定 Gradle/JDK；构建超时；不跨模块创建隐式任务依赖 |
| **验证方法** | 重复 clean build；`--configuration-cache`；`--parallel`；超时监控；构建扫描 |

### S0-R-05 Room 线程安全

| 项 | 内容 |
|---|---|
| **发生条件** | 主线程查询/写入；多写者并发；协程泄漏；事务内做 I/O |
| **影响范围** | ANR、`SQLITE_BUSY`、数据不一致 |
| **当前状态** | **PARTIAL**：`RoomTransactionRunner` 单写者 + IO dispatcher；生产代码无 `allowMainThreadQueries`；但无 StrictMode、无线程策略测试、测试中大量 `allowMainThreadQueries` |
| **防范措施** | 禁止主线程 DB；所有写走 `TransactionRunner`；`Mutex` 顺序固定；事务内不做文件/网络；Debug StrictMode |
| **验证方法** | StrictMode 检测；并发写测试；主线程查询检测；事务超时/取消测试 |

### S0-R-06 重复提交与并发写入

| 项 | 内容 |
|---|---|
| **发生条件** | 用户双击保存/入库；重试导致重复流水；两个页面同时改同一实体 |
| **影响范围** | 重复库存流水、重复单据、余额错误 |
| **当前状态** | **OPEN**：当前只有食材保存，无库存/扫码 UI；schema 有 `idempotency_key`，但无业务用例使用 |
| **防范措施** | UI 提交中禁用；幂等键唯一约束；条件更新 + `revision`；一个业务操作一个事务 |
| **验证方法** | 双击/重复请求测试；20 协程并发写；幂等键重复插入测试；流水条数断言 |

### S0-R-07 库存流水与实际库存不一致

| 项 | 内容 |
|---|---|
| **发生条件** | 直接 UPDATE 余额；流水写入失败但余额已改；事务边界错误；负库存/超预留 |
| **影响范围** | 库存数量错误、缺料清单错误、采购建议错误 |
| **当前状态** | **OPEN（高）**：表/触发器存在；无库存 UseCase/Repository/UI；无端到端库存测试 |
| **防范措施** | 余额与流水同事务；条件 UPDATE 带非负/预留约束；流水只追加；每次变更写 `change_log`；对账查询 |
| **验证方法** | 并发调整 20 协程；流水汇总 = 余额；负库存/超预留拒绝；进程死亡后一致性 |

### S0-R-08 配方版本引用失效

| 项 | 内容 |
|---|---|
| **发生条件** | 删除/覆盖已发布版本；子配方引用“当前版本”而非固定版本；发布后组成被改 |
| **影响范围** | 旧菜谱/旧计算结果变化；历史不可追溯 |
| **当前状态** | **PARTIAL**：`recipe_version`/`sauce_version` 有不可变触发器；FK 存在；无发布用例、无版本固定测试 |
| **防范措施** | 已发布版本禁止 UPDATE/DELETE；发布时解析子配方版本并写入明确 ID；旧版本只读；快照/计算记录 |
| **验证方法** | 发布后修改被拒；删除被拒；旧版本展开结果不变；FK 完整性检查 |

### S0-R-09 扫码重复识别

| 项 | 内容 |

### S0-R-10 文件恢复中断导致数据损坏

| 项 | 内容 |
|---|---|
| **发生条件** | 恢复过程中进程被杀/断电；DB 替换与 sidecar 清理不原子；备份损坏 |
| **影响范围** | 数据库损坏、无法启动、数据丢失 |
| **当前状态** | **PARTIAL**：`RestoreExecutor` + journal + 3 个测试（成功/回滚/中断恢复）；但活跃 WAL 未验证、附件未恢复、恢复 UI 未接 |
| **防范措施** | journal `PREPARED→…→DONE` + fsync + 原子替换；恢复前保留当前库；失败回滚；`integrity_check`；不删除现场 |
| **验证方法** | 强制杀进程；注入安装失败；WAL 场景；损坏备份拒绝；恢复后校验 |

### S0-R-11 自动备份“假成功”

| 项 | 内容 |
|---|---|
| **发生条件** | `AutoBackupWorker.doWork()` 直接返回 `Result.success()`，但没有创建备份；若调度器被接入，系统显示成功 |
| **影响范围** | 用户以为有备份，实际无备份；数据丢失时无法恢复 |
| **当前状态** | **OPEN（高）**：Worker 是骨架；`WorkManagerBackupScheduler` 已能入队，但当前无调用方；属于潜在缺陷 |
| **防范措施（MB-D-007 签收后）** | 实现完整备份编排后再返回 success；或明确返回 `Result.failure()`/`retry()`，不得假成功；增加“备份文件存在 + 校验通过”断言。**签收前不得修改返回逻辑。** |
| **验证方法** | 签收前：只补测试/分析，不改实现；签收后：Worker 单测、WorkManager 状态检查、备份文件存在性、失败注入 |

## 4. Stage 1 优先处理的五项

1. **S0-R-02 + S0-R-11（备份）**：**MB-D-007 未签收前只做分析、测试与修复方案**；签收后按正式任务书实现写锁 + checkpoint + 校验，并处理 Worker 返回逻辑。Stage 1 不得修改 `AutoBackupWorker`、`BackupArchiveWriter`、`RestoreExecutor`、写屏障或 checkpoint。
2. **S0-R-03（依赖检查）**：重写为配置化 + 源码 import + 拓扑排序；为 13 模块改造做准备。
3. **S0-R-01（迁移）**：Stage 1 只准备 v1→v2 迁移规范、测试模板、迁移前备份/回滚验证；**不创建正式 Schema v2**。任何 schema 变更前必须先有回档点。
4. **S0-R-12（休眠表）**：Stage 1 逐表标注 DORMANT，禁止新代码引用；**不删除、不迁移、不做结构性改造**。
5. **S0-R-13（UI 测试）**：在 Stage 3 前建立 Compose UI Test + fake UseCase 基础。

### 4.1 数据库迁移的阶段边界

| 阶段 | 允许 | 禁止 |
|---|---|---|
| Stage 0 | 核验 schema v1、记录 31 表与 11 张休眠表 | 修改 schema、Entity、DAO、迁移、数据库文件 |
| Stage 1（准备，需授权） | 迁移规范、测试模板、备份/回滚验证方案、回档点设计 | 创建正式 Schema v2、删表、迁移休眠表、改写 v1 schema |
| 未来（需授权） | 经 MB-D-005 签收并另立任务后，实施 v2 迁移 + 测试 + 备份 + 回退 | 未经授权的 destructive migration、清库、覆盖用户数据 |

**“建立迁移模板/测试”不等于“数据库迁移已实施”。**
