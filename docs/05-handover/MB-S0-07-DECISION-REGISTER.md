## 1. 使用规则

| 状态 | 含义 |
|---|---|
| `INHERITED` | G2 已接受/确认，MISEBASE 直接继承，不重新讨论 |
| `REVISED` | 继承原则，但范围/模块/实现方式被新决策修订 |
| `PROPOSED` | 接管方建议；**项目负责人签字前不作为已确认需求** |
| `PENDING` | 已提交，等待负责人决定 |
| `ACCEPTED` | 项目负责人明确接受（签字后填写） |
| `SUPERSEDED` | 被新决策取代；保留原文追溯 |
| `DEFERRED` | 明确不在当前阶段处理 |
| `N/A` | 新范围不适用 |

签字方式：在 §5 签收记录中填写「接受 / 修改 / 拒绝」、日期、签字人。AI/开发者不得自行把 `PROPOSED` 改为 `ACCEPTED`。

### 2.1 继承时必须注意

- D-004 的“15 模块不得增删”只对 G2 有效；MISEBASE 由 MB-D-003 修订，不构成对 G2 历史的改写。
- D-007 的“计划快照”不能因为删除 planning 模块而丢失语义；必须用其他载体保证“旧计算结果不因新版本变化”。
- D-011 的备份格式继承，但 E02 要求的 checkpoint 未实现；继承格式不等于继承一致性。
- D-013 的“技术选型接受”不等于“真机验证通过”。

## 3. 新增决策（建议）

> 以下均为 `PROPOSED`。签字前不作为开发依据。

### MB-D-001 接管基线与项目身份

- **建议**：接管基线 = `705e0ca`；分支 `misebase/main`；项目名 MISEBASE；包名暂留 `com.culinary`，发布前按 D-017 决定。
- **理由**：`705e0ca` 是 G2 收档提交，代码与 `2b523de` 相同，含 A-G2-001，且不含 G3 资料包。
- **影响**：标签、文档、构建名；不影响数据库。
- **阻塞**：阶段 0。

### MB-D-002 范围冻结

- **建议**：以五项功能为准；P01 的「商品/库存/计划/采购」四模块中，计划与采购移出，商品缩减，库存保留；P01 标记 `Superseded`。
- **理由**：总任务书第二部分/第三部分；避免继续按旧 P01 建采购/计划。
- **影响**：模块、导航、数据库休眠表、README、A03A、P01。
- **阻塞**：阶段 1。

### MB-D-003 目标模块集（13）

- **建议**：删除 `feature:planning`、`feature:procurement`；`feature:products` 缩减为商品/包装/条码/食材映射 + 扫码；其余保留。
- **理由**：最小改动；符合“Products 缩减”“Procurement 归 Inventory”。
- **影响**：`settings.gradle.kts`、导航、依赖检查、README、R11 历史说明。
- **阻塞**：阶段 1。

### MB-D-004 扫码 UI 归属

- **建议**：方案 A——扫码 UI 暂放 `feature:products`；若页面/代码超过拆分阈值，再拆 `feature:scan`。
- **理由**：商品与扫码同一条 `product_id` 主线；避免过早新增模块。
- **影响**：feature:products 的职责与包结构。
- **阻塞**：阶段 1（决定归属）；阶段 5（实现）。

### MB-D-005 数据库残留处置

- **建议**：schema v1 冻结；11 张规划/采购/供应商表保留但标记 `DORMANT`；不建 Repository/UI；不做删除迁移；后续如确认永久不需要，另立 schema v2 迁移任务。
- **理由**：禁止 destructive migration；避免阶段 1 因删表引入高风险；先保证范围清晰。
- **影响**：A05/A06 标注、core:database 代码入口、迁移计划。
- **阻塞**：阶段 1。

### MB-D-006 验收与测试口径

- **建议**：当前测试口径为 **197**；188 为历史漏计 `core:common` 9 例；R11/R12 以 A-G2-001 追认或由负责人补签，不修改原文；登记册补一条 `G2-S1` 说明（若负责人同意）。
- **理由**：事实一致、可追溯；不篡改历史。
- **影响**：README、A-G2-001、R19 引用、阶段报告模板。
- **阻塞**：阶段 0（确认即可，不阻塞代码）。

### MB-D-007 备份一致性优先

- **建议**：阶段 1 先补「备份前 checkpoint + 写屏障 + 活跃 WAL 恢复测试」，再进入功能开发；在完成前，备份功能不标注“一致备份”。
- **理由**：E02 明确要求；G2-U06/U09 是高风险缺口。
- **影响**：core:data backup、测试、阶段 1 范围。
- **阻塞**：阶段 1。

### MB-D-008 UI 视觉方向

- **建议**：三选一（见 UI 设计书 §3）：
  - A「专业厨房档案」：暖中性 + 橙色强调（延续现有 Orange）；
  - B「不锈钢/实验记录」：冷中性 + 蓝绿强调；
  - C「纸质索引」：米白 + 墨黑 + 深绿。
- **理由**：需要项目负责人提供参考图/品牌偏好；未确认前不宣布最终风格。
- **影响**：色彩、字体、组件、全部页面。
- **阻塞**：阶段 3。

### MB-D-009 导航信息架构

- **建议**：5 个底部入口（酱汁/食材/菜谱/库存/扫码）+ 顶栏设置；或 4 入口（总览/档案/库存/扫码）+ 档案内三库切换。
- **理由**：五项功能直接可达 vs 降低底部栏密度；需视觉/交互确认。
- **影响**：app 导航、首页、feature 路由。
- **阻塞**：阶段 3。

### MB-D-010 远端仓库与 CI

- **建议**：若有远端仓库/凭据，阶段 1 启用 GitHub Actions；否则本地门禁 + 阶段报告，CI 标 BLOCKED。
- **理由**：G2-U01；本地不能替代远端。
- **影响**：交付证据可信度。
- **阻塞**：阶段 1（如要求 CI）。

### MB-D-011 真机验证设备

- **建议**：阶段 5 前提供至少一台 Android 真机（API 26+，推荐 API 33+）；扫码/SAF/恢复必须真机验证。
- **理由**：G2-U02/U03；模拟器不能替代相机/SAF。
- **影响**：阶段 5/6 验收。
- **阻塞**：阶段 5。

### MB-D-012 发布签名策略

- **建议**：发布前创建独立 release keystore，仓库外双备份，密码分离；Debug/Release 隔离。
- **理由**：G5 门禁；G2 Release 为 unsigned。
- **影响**：发布流程、产物归档。
- **阻塞**：阶段 6。

### MB-D-013 子配方版本固定时点

- **建议**：草稿可指向“当前版本”；**发布时解析并写入明确版本 ID**；已发布版本不再跟随。
- **理由**：D-006；旧计算结果稳定。
- **影响**：recipe_version/sauce_version 发布用例、component 表。
- **阻塞**：阶段 2。

### MB-D-014 库存扣减模式

- **建议**：先计算预览（需求/可用/缺口），用户确认后写流水；默认不创建预留，除非用户选择“预留”。
- **理由**：D-010 OPEN；避免确认前产生副作用。
- **影响**：inventory 用例、reservation 表、UI。
- **阻塞**：阶段 4。

### MB-D-015 可选配料缺料口径

- **建议**：支持 `is_optional`；默认不计入缺口，详情中单独显示。
- **理由**：D-018 OPEN；避免默认缺料虚高。
- **影响**：RequirementAggregator、缺料清单。
- **阻塞**：阶段 2。

### MB-D-016 采购清单形态

- **建议**：不落 `purchase_order*` 表；按需求 - 可用计算，展示/导出清单；采购清单属于 Inventory。
- **理由**：总任务书明确；避免采购模块回流。
- **影响**：inventory UI、休眠表。
- **阻塞**：阶段 4。

### MB-D-017 计划快照替代

- **建议**：不建计划模块；用「计算记录」保存 recipe_version_id、输入份数、需求行、引擎版本、payload_hash；确认后不可变，供旧结果回放。
- **理由**：D-007 语义保留；不引入独立规划体验。
- **影响**：domain snapshot、inventory 计算、可能的 material_requirement* 表复用。
- **阻塞**：阶段 2。

### MB-D-018 文档修正授权

- **建议**：授权阶段 0 做一次纯文档修正：README 的数据库/测试/决策状态；P01 顶部加 Superseded 说明；A03A 加 13 模块修订说明；不修改历史报告正文。
- **理由**：README 失真会误导开发。
- **影响**：文档；不影响代码。
- **阻塞**：阶段 0。
