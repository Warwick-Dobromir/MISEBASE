## 4. 第 2 项：数据模型核验

- 31 张表，覆盖：单位/食材/酱汁/菜谱/版本/组成、商品/条码/供应商、批次/流水/预留/位置、计划/快照/需求/来源、采购/收货、图片、变更日志、备份记录、元数据。
- 关键关系：
  - 食材 1—N 商品；商品 1—N 批次；批次 1—N 流水/预留；
  - 菜谱/酱汁版本不可变，组成行固定子版本；
  - 计划项固定 `recipe_version_id`，确认生成不可变快照；
  - 采购收货创建批次与流水，关联采购明细。
- 约束：外键、唯一（条码/版本/幂等键）、CHECK（库存非负/预留 ≤ 在手/组成三选一）、部分唯一索引、流水 append-only 触发器。
- 删除：历史数据 `RESTRICT`；只允许草稿聚合 `CASCADE`；批次/流水/已确认计划不硬删。
- 迁移：Room schema 导出、前向迁移、迁移前备份、失败恢复；禁止破坏性降级。

## 6. 第 4 项：并发与数据库安全核验

- WAL + 单写者 `WriteGate`；所有前台/后台写入经同一 `writeMutex`。
- 事务边界在 Use Case；Repository 不自行开事务；禁止嵌套写锁。
- 条件更新防负库存/超卖；`revision` 乐观锁；`idempotency_key` 防重复过账。
- `busy_timeout`、有限重试（50/150/400 ms）、超时、锁冲突分类。
- 迁移前备份；迁移失败回滚；DB 损坏隔离不删除；从验证备份恢复。
- 备份/恢复与写入协调：checkpoint 结果检查、活动读连接等待/重试/终止、源库健康检查。
- 测试计划包含 20 协程并发、BUSY 注入、进程死亡、损坏、恢复中断。
