## 1. 结论摘要

**架构层面已经具备进入框架搭建的条件；工程环境层面还差 4 项门禁。**

- 产品边界、技术选型、分层、模块、数据模型、业务流程、并发/备份/测试方案已经形成完整基线。
- 依赖兼容性已经用真实构建验证（AGP 8.13 + Kotlin 2.2.20 + Hilt 2.57.2 + Room 2.8.5 + Compose 2025.10.01）。
- 当前不具备“无条件开工”的状态，原因不是架构未想清楚，而是：
  1. 8 项关键决策尚未由项目负责人签收；
  2. `JAVA_HOME` / `ANDROID_HOME` 未配置；
  3. 模拟器安装/启动未完成（构建已通过，安装待验证）；
  4. Release 签名 keystore 尚未创建/备份。

**结论：完成上述 4 项后，可直接按 R01 开始框架搭建，不需要重新讨论“软件应该怎么做”。**

## 3. 已锁定的技术决策

> 下列为**架构基线锁定**；其中 8 项需项目负责人签收后才升级为 `Approved`。

| # | 决策 | 结论 |
|---|---|---|
| 1 | 平台 | 原生 Android；Kotlin + Compose；不跨平台（D-001） |
| 2 | SDK | min 26 / compile & target 36（D-002） |
| 3 | 数据库 | Room 2.8.5 + 平台 SQLite；WAL；单进程单写者；不 SQLCipher（D-003） |
| 4 | 架构 | 16 模块；`app → feature → domain ← data → database`；feature 间禁止依赖（D-004） |
| 5 | 配方 | 不可变已发布版本 + 当前版本；计划项固定版本（D-006） |
| 6 | 历史 | 计划确认生成不可变快照；刷新生成新 revision（D-007） |
| 7 | 单位 | 维度 + 基准因子；跨维度只允许食材级显式换算；无依据拒绝（D-008） |
| 8 | 库存 | 批次 + 位置 + 追加式流水 + 预留；禁止直接改数（D-009） |
| 9 | DI | Hilt 2.57.2（AGP 8.13 兼容上限）（D-012） |
| 10 | 扫码 | CameraX + ML Kit Bundled；本地优先；手工输入兜底（D-013） |
| 11 | 备份 | 自定义 ZIP + manifest + SHA-256；可选 AES-GCM；恢复可回滚（D-011） |
| 12 | 云/AI | 本阶段不做账号、同步、协作、AI 核心（D-014） |

**为什么这些必须现在锁定：** 它们决定工程骨架、数据库结构、备份兼容和平台适配；在框架搭好后再换，等于重写。

## 6. 正式框架制作的推荐顺序

严格按 [R01](R01-FRAMEWORK-SEQUENCE.md)，不要跳阶：

1. **阶段 0 环境门禁**：JDK/SDK 环境变量、依赖解析、空工程构建/安装、签名。
2. **阶段 1 工程骨架**：16 模块、版本目录、约定插件、空白页。
3. **阶段 2 核心契约**：Outcome/错误、model、domain 端口、单位/图算法骨架。
4. **阶段 3 数据库 v1**：31 表、索引、约束、种子、迁移框架。
5. **阶段 4 数据层**：Repository、Mapper、事务、文件、备份骨架。
6. **阶段 5 平台能力**：扫码、权限、SAF、WorkManager。
7. **阶段 6 应用外壳**：Hilt、导航、启动/恢复。
8. **阶段 7 纵向切片**：食材 CRUD（最小 UI）打通全链路。
9. **阶段 8 算法验证**：循环、单位、展开、汇总、缺口。
10. **阶段 9 质量门禁**：CI、迁移、备份冒烟、基线标签。

**不要在阶段 1 就做八个模块的 UI。** 先让数据/事务/算法可验证，再做界面。

### 7.3 开工后前 10 个动作

1. 初始化 Git 仓库 + `.gitignore` / `.gitattributes` / `.editorconfig`。
2. 创建 `settings.gradle.kts` + 16 模块 + 版本目录。
3. 配置镜像优先仓库 + Gradle Wrapper 8.14.3（带校验和）。
4. 建 `app` 空白工程，`assembleDebug` + 安装。
5. 加 manifest 权限移除规则，`aapt` 验证无 INTERNET。
6. 建 `core:common` 的 `Outcome` / 错误码 / 日志接口。
7. 建 `core:database` v1：先 units/ingredient/recipe/plan 核心表，逐步补齐。
8. 建 `TransactionRunner` + 单写者 + PRAGMA 自检。
9. 打通食材纵向切片。
10. 加 CI（lint/unit/db/assemble）+ 权限检查 + 迁移测试骨架。
