## 6. 正式框架制作的推荐顺序

严格按 [R01](R01-FRAMEWORK-SEQUENCE.md)，不要跳阶：

1. **阶段 0 环境门禁**：JDK/SDK 环境变量、依赖解析、空工程构建/安装（Debug）。
2. **阶段 1 工程骨架**：按 D-004 审查后的模块集（推荐 13）、版本目录、约定插件、空白页。
3. **阶段 2 核心契约**：Outcome/错误、domain（含模型）、端口、单位/图算法骨架。
4. **阶段 3 数据库 v1**：31 表、索引、约束、种子、迁移框架。
5. **阶段 4 数据层**：Repository、Mapper、事务、文件、备份骨架。
6. **阶段 5 平台能力**：扫码、权限、SAF、WorkManager。
7. **阶段 6 应用外壳**：Hilt、导航、启动/恢复。
8. **阶段 7 纵向切片**：食材 CRUD（最小 UI）打通全链路。
9. **阶段 8 算法验证**：循环、单位、展开、汇总、缺口。
10. **阶段 9 质量门禁**：CI、迁移、备份冒烟、基线标签。

**不要一次做完所有 feature 的 UI。** 先让数据/事务/算法可验证，再做界面。

### 7.2 开工前必须完成的 1 项

| # | 行动 | 完成标准 |
|---|---|---|
| 1 | 整体签收 G1（8 项决策） | D-004 模块方案审查 + D-011 备份补充复核；DECISION-REGISTER 记录整体签收 |

> 依赖解析、版本锁定、构建、模拟器安装/启动、环境变量均已完成。G5 已调整为发布门禁，不阻塞框架。

### 7.3 发布前门禁（不阻塞框架）

- 创建 Release keystore，Debug 与 Release 严格隔离；
- keystore 不入 Git、不在源码硬编码密码；
- 至少两份独立加密备份；
- 验证密钥、密码、证书指纹；
- Release 签名验证纳入发布检查清单。

### 7.4 开工后前 10 个动作

1. 初始化 Git 仓库 + `.gitignore` / `.gitattributes` / `.editorconfig`。
2. 按 D-004 审查结论创建模块（推荐 13）+ 版本目录。
3. 配置镜像优先仓库 + Gradle Wrapper 8.14.3（带校验和）。
4. 建 `app` 空白工程，`assembleDebug` + 安装。
5. 加 manifest 权限移除规则，`aapt` 验证无 INTERNET。
6. 建 `core:common` 的 `Outcome` / 错误码 / 日志接口。
7. 建 `core:database` v1：先 units/ingredient/recipe/plan 核心表，逐步补齐。
8. 建 `TransactionRunner` + 单写者 + PRAGMA 自检。
9. 打通食材纵向切片。
10. 加 CI（lint/unit/db/assemble）+ 权限检查 + 迁移测试骨架。
