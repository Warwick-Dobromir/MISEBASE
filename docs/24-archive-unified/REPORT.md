## 1. 完成内容

### 1.1 分类体系

新增 3 张表：

```text
archive_category              六库分类树（library / parent_id / sort_order / test_batch）
archive_category_assignment   档案与分类节点的一对一归属
kitchen_reference_content     烹饪技术/制作标准/储存标准的专业字段与可排序条目
```

未修改六张档案主表（`sauce`、`ingredient`、`recipe`、`kitchen_reference`）。

- 六库隔离：`SAUCE` / `INGREDIENT` / `RECIPE` / `TECHNIQUE` / `PRODUCTION_STANDARD` / `STORAGE_STANDARD`。
- 任意层级：`parent_id` 自引用；不写死层级。
- 排序：`sort_order` 持久化，同父排序。
- 一个档案一个分类节点；assignment 唯一。
- 分类与档案分离；分类节点可同时有子分类和档案。
- 分类不在编辑器中创建。
- 正式分类按现有分类值首次出现顺序迁移；记录在 v6 迁移与 seed 中确定。
- 旧 `family/category` 字符串保留，作为兼容回退。

```text

```

步骤：

## 5. 已知边界

- 正式数据本身只有一级分类；三级能力由独立测试树在 APK 中实际展示。正式数据的专业多级整理需要后续分类内容任务，不在本次擅自虚构。
- 现有参考资料数据只有 description；新专业字段为空时不显示，不用占位或假数据填充。
- 食材/菜谱现有测试数据没有图片资产；图片读取链路已接通，但没有图片时不显示占位图。
- 其他库（食材/菜谱/参考资料）编辑器仍使用原有分类文本；本次分类选择器只接入任务指定的酱汁编辑器。新档案没有分类节点时会在目录根部“档案”区出现，不会被隐藏或丢失。
- 详情页使用现有档案阅读骨架并补齐路径/图片/专业内容；没有改动首页、库存、采购、扫码、计时器、底部导航和全局主题。
