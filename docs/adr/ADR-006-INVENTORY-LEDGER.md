# ADR-006：批次 + 流水 + 预留的库存模型

**状态**：Proposed
**版本**：`0.1.0`
**日期**：2026-11-04
**决策者**：首席架构师 / 项目负责人
**关联**：D-009、A04、A06、E02

## 背景

需求要求库存关联实际商品、支持批次/位置、区分实际/预留/可用、所有变化可追溯，禁止直接改库存数字。

## 决策

1. 库存按商品 + 批次 + 储存位置管理。
2. `quantity_on_hand` 是物化余额；`quantity_reserved` 是预留；可用 = 在手 - 预留。
3. 所有变化写 `inventory_ledger`；流水只追加，禁止 UPDATE/DELETE。
4. 余额更新使用条件 SQL，禁止负库存/预留超在手。
5. 计划确认默认预留可用部分；出库才实际扣减。
6. 批次不硬删；耗尽/报损用状态表达。

## 理由

- 只有余额无法解释“为什么是这个数”。
- 预留与实扣分离，才能支持计划占用和实际制作。
- 批次/位置支持到期、FEFO、追溯。
- 流水审计是数据恢复与纠错的基础。

## 后果

- 写入路径更长（余额 + 流水 + 预留）。
- 需要事务与并发控制（E02）。
- 用户需要理解“可用”与“在手”的区别。
- 盘点/调整必须填原因。

## 替代方案

- 单一库存数字：无法审计/批次/预留，拒绝。
- 只按食材：无法对应实际商品，违背已确认规则。

## 复审条件

- 业务确认不需要批次（与已确认需求冲突）；
- 性能瓶颈需要物化汇总表，但流水仍是事实源。
