# ADR-005：单位维度与“禁止无依据换算”

**状态**：Proposed
**版本**：`0.1.0`
**日期**：2026-11-04
**决策者**：首席架构师 / 项目负责人
**关联**：D-008、A04、A06

## 背景

配方中会出现 g、kg、ml、杯、勺、个、束、瓣等单位。质量与体积不能随意互换；不同食材的“一杯”重量不同。

## 决策

1. 每个单位有维度：`MASS`、`VOLUME`、`COUNT`。
2. 同维度按基准因子换算；`COUNT` 不同单位不自动互转。
3. 跨维度换算必须存在**食材级**显式换算记录（密度/单件重量），并显示依据。
4. 无依据时返回 `CUL-UNIT-001`；需求汇总分行并标记“不可换算”，不猜测。
5. 近似换算（tsp/cup）标记 `is_approximate`，界面显示“约”。

## 理由

- 防止 1 杯面粉被错误当成 240 g。
- 保留专业判断：换算依据由用户提供，不由软件臆测。
- 让缺口计算可解释、可审计。

## 后果

- 用户需要为特殊单位维护食材级换算。
- 不可换算时无法自动合并/比较库存；需要手工处理。
- 单位精度/舍入需统一策略。

## 替代方案

- 使用通用密度表：对不同食材不准确，拒绝。
- 只允许基准单位：录入体验差，且无法表达“1 杯”。

## 复审条件

- 引入权威食材密度库且用户确认；
- 业务决定允许“估算值”并明确标注。
