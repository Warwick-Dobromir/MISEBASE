## 1. 产品视觉定位

### 1.1 一句话

> **一个专业厨房工作台，不是一本菜谱杂志。**

MISEBASE 的界面首先服务于“查数据、改配方、算物料、看库存、扫码入库”，其次才是“好看”。它应该像一张干净的厨房工作台：东西都有固定位置，标签清楚，手上有水也能点准，光线差也能读清。

### 1.2 视觉方向（A 已签收）

| 方向 | 关键词 | 色彩 | 气质 | 风险 |
|---|---|---|---|---|
| **A 专业厨房档案**（**已签收**，2026-11-04） | 暖中性、橙色强调、纸张感 | 现有 Orange `#B4551F` + 暖灰 | 亲切但不花哨；适合长期使用 | 橙色用多会显“餐饮营销感”，需克制 |
| B 不锈钢/实验记录 | 冷中性、蓝绿强调、精密 | 冷灰 + 深青 | 更“研发/实验室” | 厨房场景偏冷；与现有主题差异大 |
| C 纸质索引 | 米白、墨黑、深绿 | 米白 + 墨 + 深绿 | 像一本厨师笔记/档案册 | 对比度与暗色主题更难做 |

**结论 A（MB-D-008，2026-11-04）**：暖中性底色 + Orange 强调 + 暖灰辅助；现代、清晰字体；
组件简洁克制；用留白、字重、间距建立层级。B/C 仅作历史备选，不再作为候选。

### 1.3 使用场景约束

- 手机为主，单手操作；
- 厨房环境：可能有水、油、手套；触控目标 ≥48dp；
- 光线变化大：不能依赖低对比灰字；
- 网络不稳定/无网络：所有状态必须本地可见，不出现“转圈等网络”；
- 长期使用：视觉要耐看，不追潮流。

## 2. 设计原则

1. **数据优先**：数量、单位、版本、状态永远比装饰重要。
2. **结构稳定**：同类页面同一布局；按钮位置不随内容跳动。
3. **克制**：不用渐变、玻璃、重阴影、无意义动画。
4. **直接**：常用操作一屏可达；不做多层隐藏菜单。
5. **可读**：中文正文不小于 14sp；关键数量用等宽数字。
6. **一致**：颜色/间距/圆角只来自 token，页面不写魔法值。
7. **可恢复**：危险操作必须确认；失败必须说明“下一步做什么”。
8. **可维护**：页面特有视觉留在页面内；共享组件必须有明确边界。

- 不用纯黑 `#000000` 与纯白 `#FFFFFF` 作为大面积背景；
- 语义色（success/warning/danger）不用于装饰。

## 4. 字体与排版

### 4.1 字体

- 中文：Android 系统默认（Noto Sans CJK / 厂商字体）；
- 拉丁/数字：Roboto / 系统 sans；
- 代码、条码、ID：等宽（`monospace`）；
- **不引入第三方字体**，除非品牌确认且包体可接受。

### 4.2 字阶（sp）

| Token | 字号/行高 | 用途 |
|---|---|---|
| `display` | 32 / 40 | 首页大标题（少用） |
| `headline` | 24 / 32 | 页面标题 |
| `title` | 20 / 28 | 区块标题 |
| `subtitle` | 16 / 24 | 列表主标题/卡片标题 |
| `body` | 14 / 22 | 正文 |
| `label` | 12 / 16 | 标签/按钮辅助 |
| `caption` | 11 / 16 | 时间/单位/次要说明 |

### 4.3 规则

- 关键数量（g/ml/份）使用**等宽数字**（`tnum`），右对齐或按小数点对齐；
- 单位与数字分离：数字 16–20sp medium，单位 12sp secondary；
- 中文正文行高 ≥1.5；
- 不自动缩小字体来塞内容；优先换行/省略/详情页；
- 最多两级标题；列表内不再嵌套大标题；
- 支持系统字体缩放 1.3× 不截断；2.0× 时允许滚动，不重叠。

## 5. 间距系统

### 5.1 基础

- 基准 **4dp**；
- 允许值：`4, 8, 12, 16, 24, 32, 48`；
- 页面左右边距：**16dp**（紧凑屏）/ 24dp（大屏）；
- 区块间距：24dp；卡片内边距：16dp；列表行垂直：12–16dp；
- 表单字段间距：16dp；按钮组间距：12dp。

### 5.2 规则

- 不允许 5/7/10/13 等非 4 倍数（图标光学修正除外）；
- 同层级元素间距一致；
- 底部操作栏预留系统手势区 + 16dp；
- 列表最后一项留 88dp，避免 FAB/底栏遮挡。

## 6. 圆角与表面层级

| Token | 值 | 用途 |
|---|---|---|
| `radius.xs` | 4dp | 标签/chip |
| `radius.sm` | 8dp | 按钮/输入框 |
| `radius.md` | 12dp | 卡片/列表容器 |
| `radius.lg` | 16dp | BottomSheet/大卡片 |
| `radius.full` | 999dp | 圆形头像/徽标 |

- 阴影只用于浮层（Dialog/BottomSheet/FAB），列表/卡片用 1dp 边框或色差；
- 不使用彩色阴影、重投影；
- 表面层级最多 2 层（背景 → 卡片/浮层）；不要卡片套卡片。

## 7. 图标规范

- 风格：Material Symbols Outlined（线性）；
- 尺寸：20dp（行内）/ 24dp（导航/按钮）；
- 选中态可用 Filled，但同一导航内保持一致；
- 图标必须有文字标签（底部导航）或 `contentDescription`；
- 不用 emoji 作为功能图标；
- 不用图标替代关键数据（如库存数量必须显示数字）；
- 自定义图标只用于扫码/食材分类等必要场景，需统一线宽。

---

## 8. 按钮与输入规范

### 8.1 按钮

| 类型 | 高度 | 用途 |
|---|---|---|
| Primary（填充） | 48dp | 每屏最多 1 个主操作 |
| Secondary（描边） | 48dp | 次要操作 |
| Text | 40dp | 低优先级/行内 |
| Danger | 48dp | 删除/恢复覆盖等破坏性操作 |
| IconButton | 48×48dp | 顶栏/行尾 |

规则：

- 圆角 8dp；文字 14–16sp medium；
- loading 时保留按钮宽度，显示 spinner + 原文字；
- 禁用态降低对比但保持可读；
- 防双击：提交后 500ms 内忽略重复点击；
- 一屏不要超过 2 个同等权重的主按钮。

### 8.2 输入

- 高度 56dp（OutlinedTextField）；
- 标签在输入框上方或浮动，不用 placeholder 当标签；
- 必填用 `*` + 说明；错误文字在下方，danger 色；
- 数字输入：`KeyboardType.Decimal/Number`；单位作为 suffix；
- 数量步进器：`− [数值] +`，长按连续调整；步长按单位（g=1/10/50，ml=1/10/50，份=1）；
- 单位选择器：底部弹层，显示维度与换算关系；
- 不支持换算时，输入框下方明确“无法换算”，不允许静默取整；
- 文本长度限制可见（如名称 80 字），超限提示而非截断。

---

## 9. 列表与详情布局

### 9.1 列表

- 行高：单行 56dp / 双行 72dp / 三行 88dp；
- 结构：`[可选图标] 标题 / 副标题 / 尾部数量或状态`；
- 标题 16sp；副标题 14sp secondary；尾部数量等宽数字；
- 分隔线 1dp `outlineVariant`，左侧缩进与文字对齐；
- 分组标题 sticky；分组内不重复大标题；
- 排序/筛选放在顶栏下方，不放在滚动内容里；
- 空列表不显示“假行”。

### 9.2 详情

- 顶栏：返回 + 标题 + 操作（编辑/更多）；
- 摘要区：名称、状态、版本、标准产量；
- 分区：配方 / SOP / 成品标准 / 版本历史 / 关联；
- 数量表：原料名 | 数量 | 单位 | 处理说明；右对齐数量；
- 长内容用可折叠 section，但默认展开关键信息；
- 底部固定主操作（编辑/开始计算/入库），不随滚动消失；
- 历史版本入口必须在首屏可见。

---

## 10. 表单规范

- 单列布局；大屏最大宽度 720dp；
- 按语义分组，每组一个标题；
- 保存按钮在底部固定栏；取消/返回时若有未保存修改，弹确认；
- 校验时机：失焦 + 提交；错误定位到字段；
- 不允许“保存成功但字段被静默丢弃”；
- 复杂编辑（配方组成/SOP）用可排序行 + 明确增删按钮，不依赖长按拖拽作为唯一方式；
- 表单内不嵌套滚动列表（用整页滚动）；
- 自动保存仅用于草稿，且必须显示“草稿已保存”状态。

---

## 11. 弹窗与确认流程

- 确认弹窗：标题 + 一句后果 + 取消/确认；破坏性操作确认按钮用 danger；
- 二次确认仅用于：恢复备份、删除有库存商品、清空数据；
- 选择器（单位/食材/酱汁/版本）用 BottomSheet，不用多层 Dialog；
- 不允许 Dialog 套 Dialog；
- 弹窗最大宽度 560dp；内容可滚动；
- 确认文案必须说明“会发生什么”，不能只写“确定吗？”；
- 危险操作默认焦点在“取消”，不默认选中“删除”。

## 12. 空状态

结构：

```text
[线性图标 48dp]
标题（16sp）
一句解释（14sp secondary）
[主操作按钮]（可选）
```

规则：

- 说明“为什么空”和“下一步做什么”；
- 不用空白插画占位；
- 搜索无结果 ≠ 列表为空：文案区分；
- 空状态不显示筛选栏的“0 条”作为唯一信息。

---

## 13. 加载状态

- 首次加载列表/详情：骨架屏（3–6 行），不用全屏 spinner；
- 局部操作：按钮内 spinner 或行内进度；
- 备份/恢复/迁移：全屏进度页 + 当前阶段文字（准备/校验/写入/完成），不显示假百分比；
- 刷新：顶部细进度条，不遮挡内容；
- 超过 2s 的操作显示“仍在处理”；
- 不允许无限 spinner：失败必须进入错误态。

---

## 14. 错误状态

### 14.1 层级

| 层级 | 场景 | 呈现 |
|---|---|---|
| 字段级 | 名称重复、数量非法 | 输入框下方红字 |
| 页面级 | 列表加载失败、数据库打不开 | 整页错误态 + 重试/恢复 |
| 全局 | 迁移失败、数据库损坏 | Recovery 页，禁止继续写入 |
| 操作级 | 保存失败、库存不足 | Snackbar + 详情 |

### 14.2 文案

- 用户能看懂：发生了什么 + 数据是否安全 + 下一步；
- 同时记录错误码（如 `CUL-DB-002`），便于诊断；
- 不显示原始 SQL/堆栈；
- 单位无法换算：明确列出“哪一行、哪个单位、缺什么依据”。

### 14.3 特殊错误

- 相机权限拒绝：说明 + 去设置 + 手工输入兜底；
- 无匹配条码：创建商品/映射食材/取消；
- 库存不足：显示需求/可用/缺口，建议调整数量或补货；
- 备份校验失败：拒绝恢复，保留现场，提供诊断导出。

## 15. 成功反馈

- 普通保存：Snackbar 2–4s，“已保存”+ 可撤销（仅可逆操作）；
- 入库/出库：Snackbar + “查看流水”动作；
- 备份完成：显示文件位置/大小/校验结果；
- 恢复完成：显示恢复点时间 + 数据校验结果；
- 不用 confetti/全屏动画；
- 不遮挡底部主操作；
- 成功文案不夸大（“已保存”不是“已同步”，因为无云）。

## 16. 导航体系

### 16.1 导航方案（N1 已签收）

**方案 N1：5 个底部入口（**已签收**，2026-11-04，MB-D-009）**

```text
[酱汁] [食材] [菜谱] [库存] [扫码]
顶栏：页面标题 + 设置图标
```

- 五项功能直接可达；
- 设置不占底部栏；
- 三大知识库（酱汁/食材/菜谱）保持独立一级入口；
- 扫码保留底部一级入口；
- 允许调整图标、文案与视觉表现，**不得改变信息架构**。

**方案 N2：4 个底部入口 + 档案枢纽（历史备选，未采用）**

```text
[总览] [档案] [库存] [扫码]
档案内顶部 Tab：酱汁 / 食材 / 菜谱
```

- 底部栏更轻；
- 三库归类清晰；
- 五项功能多一次点击。

**结论 N1（MB-D-009，2026-11-04）**：五个底部一级入口，设置放顶栏；N2 不再作为候选。
实际导航实现与图标/文案细化在 Stage 3 任务书中处理。

### 16.2 规则

- 单 Activity + Navigation Compose；
- 底部导航保留状态（切换 tab 不重置滚动/输入）；
- 返回键：先关弹层 → 再返回上一页 → 最后退出；
- 详情页不显示底部导航（沉浸编辑），或保留但禁用？建议编辑页全屏；
- 路由名稳定，不为了“好看”改名；
- 暂不做 deep link；如做，必须有测试。

## 17. 页面交互规范

- 触控目标 ≥48×48dp；
- 点击有水波纹/按压态；
- 长按只用于“更多操作”，不作为唯一入口；
- 滑动删除仅用于可恢复项（如归档），且提供撤销；
- 搜索：输入 300ms 防抖；清空按钮；无结果文案；
- 筛选：Chip 多选/单选明确；显示“已选 N 项”；可一键清除；
- 排序：名称/更新时间/版本；当前排序可见；
- 数字输入：允许小数，按单位精度显示；不允许科学计数法；
- 防止重复提交：保存/入库/恢复按钮在处理中禁用；
- 离开未保存表单：确认弹窗；
- 任何“计算”动作先显示输入摘要（菜谱/份数/版本），再显示结果。

---

## 18. 无障碍与触控尺寸

- 触控 ≥48dp；行内图标按钮 48dp 命中区；
- 正文对比 ≥4.5:1；大字号 ≥3:1；
- 不仅靠颜色传达状态（库存不足用文字/图标）；
- 所有图标按钮有 `contentDescription`；
- TalkBack 顺序 = 视觉顺序；分组标题可聚焦；
- 支持字体缩放 1.3×/2.0×；不截断关键数量；
- 支持系统“移除动画”设置；
- 扫码页提供声音/震动反馈（可关闭），不只靠视觉；
- 表单错误同时用文字 + 颜色。

---

## 19. 屏幕尺寸适配

| 宽度 | 策略 |
|---|---|
| < 600dp（手机） | 单列；底部导航；全屏编辑 |
| 600–840dp（小 tablet/折叠展开） | 列表 + 详情双栏（可选）；表单最大 720dp |
| > 840dp（tablet） | 双栏；导航可改侧栏（后续） |

- 手机横屏：编辑页允许滚动，不强制双栏；
- 折叠屏：不假设固定宽度；用 WindowSizeClass；
- 超长名称：最多 2 行省略，详情页完整显示；
- 大字体 + 小屏：优先滚动，不缩小字体。

---

## 20. 深浅主题策略

- **首版建议：跟随系统，亮色优先**；
- 暗色不是简单反色：背景 `#1A1210`，表面 `#241A16`，主色提亮；
- 图片/条码在暗色下保持可读；
- 状态色在暗色下重新取对比，不直接复用亮色；
- 提供“仅亮色/仅暗色/跟随系统”设置（后续）；
- 两套主题都必须跑视觉验收清单。

---

## 21. 组件复用边界

### 21.1 Design System 负责

- Token：颜色、字体、间距、圆角、阴影；
- 基础组件：Button、TextField、Card、ListRow、SectionHeader、EmptyState、ErrorState、Loading、Dialog、BottomSheet、Snackbar、SearchField、FilterChip、QuantityText、UnitLabel、StatusBadge；
- 组件只含视觉/交互，不含业务规则。

### 21.2 Feature 负责

- 页面布局与页面状态；
- 业务组件：RecipeComponentRow、SauceVersionBadge、InventoryLedgerRow、ScanOverlay、RequirementTable；
- 只在本 feature 内复用的组件放 `presentation/components/`。

### 21.3 规则

- 修改共享组件前，列出调用方与影响；
- 页面特有需求优先在页面内实现，不轻易上升为全局组件；
- Design System 不变成业务页面代码集中地；
- 共享组件变更必须跑相关页面截图/测试。

## 22. 页面视觉验收规则

每个页面交付前逐项检查：

- [ ] 使用 token，无魔法色值/间距；
- [ ] 标题/正文/辅助字号符合字阶；
- [ ] 关键数量等宽数字、单位分离、右对齐；
- [ ] 360dp 宽无横向滚动/截断；
- [ ] 字体缩放 1.3× 不重叠；2.0× 可滚动；
- [ ] 亮色/暗色对比度达标；
- [ ] 触控目标 ≥48dp；
- [ ] 空/加载/错误/成功四态齐全；
- [ ] 返回/取消/未保存确认正确；
- [ ] 无重复提交；
- [ ] TalkBack 主要路径可走通；
- [ ] 与相邻页面视觉一致（同层级同布局）；
- [ ] 截图归档到阶段报告。
