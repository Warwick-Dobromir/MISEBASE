## 1. 使用规则

- `CONFIRMED`：来自任务书或项目负责人明确指示，不得擅自更改。
- `ACCEPTED`：项目负责人已明确接受该单项；但 G1 需在修订版整体复核后才通过，不提前宣称“全部签收”。
- `PENDING`：已提交修订，等待负责人复核；不可作为开工依据。
- `REVISION`：负责人要求修改/补充后重新提交；当前版本不可作为开工依据。
- `PROPOSED`：架构师给出的推荐决策。**在项目负责人签收前不作为已确认需求**。
- `OPEN`：产品规则缺口。已给出推荐默认值，标注是否阻碍框架搭建。
- `DEFERRED`：明确不在本阶段处理，保留扩展缝。
- `DEFERRED-RELEASE`：不作为框架开工门禁，但必须在正式发布前完成。

签收方式：在本文末尾“签收记录”中填写决定（接受 / 修改 / 拒绝）与日期。`ACCEPTED` 只表示单项接受；G1 仍需修订版整体签收。

## 3. 关键决策说明

### D-001 为什么必须现在锁定平台

平台选择决定 UI、导航、扫码、文件、后台任务、测试和打包的全部实现方式。若先做 Flutter，再因为离线数据库、扫码或文件恢复能力回退原生，等于重写表现层与平台适配层。CULINARY 只面向 Android，跨平台收益接近于零，因此原生是默认且推荐的基线。

### D-006/D-007 版本与快照是两个不同问题

- **配方版本**解决“配方自身如何演进”。
- **计划快照**解决“历史计划如何不被后续修改影响”。

只有配方版本而没有计划快照，仍然会在“旧计划引用了可变配方”时出错；只有计划快照而没有配方版本，则无法解释某个计划用的是哪一版配方。两者都必须有。

### D-008 不允许“看起来合理”的换算

`1 cup = 240 ml` 可以作为显式、可审查的近似换算；`1 cup 面粉 = 120 g` 必须绑定到“面粉”这个食材，不能作为通用规则。没有密度、没有食材级换算时，系统必须显示“无法换算”，而不是猜一个数。

### D-009 库存不是一列数字

库存 = 批次余额 + 流水 + 预留。`quantity_on_hand` 只是物化余额，任何变化都必须有对应流水。这样“商品删除但库存仍在”“并发写入”“盘点调整”才有可追溯的答案。

### D-004 模块数量不是架构目标（已接受）

负责人已接受 **15 模块方案**：

- 合并 `core:model` 到 `core:domain`（包级保持 model/rule/usecase 边界）；
- 酱汁 `feature:sauces` 与菜谱 `feature:recipes` **保持独立**，通过 domain 端口与版本引用交互；
- 商品 `feature:products` 与库存 `feature:inventory` **保持独立**，通过 `product_id` 与 domain 端口交互；
- 保留 `core:database` 独立、`core:data` 独立、feature 间零依赖；公共能力归 core；
- 保持 DAG 与现有依赖方向。

**附加边界：**

- `core:platform` 负责 SAF、系统文件选择器、权限等 Android 能力；
- `core:data` 负责备份格式、校验、打包/解包、恢复编排；
- `core:data` 不直接依赖 Android SAF，不使用 `Uri` 作为领域接口；
- 两者通过 `BackupStoragePort`/`StorageHandle` 或 app 适配桥接；
- 不允许为实现备份破坏模块依赖规则。

详见 [A03A](../02-architecture/A03A-MODULE-DECOMPOSITION-REVIEW.md) 第 8.1 节。**D-004 = ACCEPTED。**

### D-011 备份不是“打个 ZIP”（ACCEPTED）

负责人接受自定义 ZIP 方向。E05 0.3.0 曾暂不签收；0.4.0 已按五项复核意见修订，0.4.1 进一步修复 MIME/大小异常与 PARTIAL 恢复二次确认：

1. 修复 manifest 自哈希循环；
2. 修正 schema 版本判断方向；
3. 缺失图片默认失败，`PARTIAL` 仅用户明确继续；
4. journal INTENT/DONE + 幂等恢复；
5. checkpoint 结果检查、读连接策略、写屏障覆盖、源库健康检查。

[E05](../03-engineering/E05-BACKUP-RESTORE.md) 为 `0.4.1` / `Approved`；复核证据见 [E05A](../03-engineering/E05-REVISION-REVIEW.md)。**D-011 = ACCEPTED。**

### D-014 明确不做的事情

本阶段**不**设计云同步协议、账号体系、多人权限、AI 生成配方。数据模型只保留低成本扩展缝：UUID 主键、`updated_at`、软删除标记、仓储接口。不会为想象中的同步预建 outbox、冲突解决表或服务端代码。
