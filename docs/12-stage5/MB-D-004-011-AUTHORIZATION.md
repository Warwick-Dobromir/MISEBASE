## 2. MB-D-004 签收内容

### 2.1 决定

- **新建独立 `feature:scan`**；
- **Stage 1–4 仍为 13 模块**；**Stage 5 起模块集为 14**；
- 扫码 UI、CameraX 生命周期、ML Kit 识别归 `feature:scan`；
- 识别结果通过**明确接口**交给业务模块；
- 食材创建/导入归 `feature:products`；
- 库存操作归 `feature:inventory`；
- N1 五入口不变，扫码仍为第五个底部一级入口；
- 本次签收**不创建** `feature:scan` 目录，**不修改** `settings.gradle.kts` 或依赖检查当前期望值。

### 2.2 13 → 14 的时点

| 阶段 | 模块集 | `feature:scan` |
|---|---|---|
| Stage 1–4 | 13 | 不存在；扫码入口为占位 |
| Stage 5 起 | **14** | 新建并实现扫码 UI/CameraX/识别 |

13 不是历史错误：MB-D-003 的 13 模块是 Stage 1 目标；MB-D-004 在其上增加第 14 个模块。

### 2.3 职责边界

| 模块 | 职责 | 不负责 |
|---|---|---|
| `feature:scan` | 扫码页面、CameraX、ML Kit 识别、去抖/一次性消费、识别结果展示 | 食材创建/导入、库存扣减、商品主数据编辑 |
| `feature:products` | 商品/包装/条码/食材映射、食材创建/导入 | 相机、识别、库存余额 |
| `feature:inventory` | 入库/出库/调整/流水、库存余额 | 条码识别、食材主数据创建 |
| `app` | 导航、权限入口、模块编排 | 业务规则、识别算法 |

### 2.4 接口原则

- `feature:scan` **不直接依赖其他 feature**；
- 识别结果以结构化数据（条码值、格式、来源、时间）通过 app 导航或 `core:domain` 端口交给业务模块；
- 业务模块决定“创建食材 / 导入商品 / 入库 / 仅展示”，扫码模块不直接写业务表；
- 权限请求、CameraX 生命周期与识别去抖留在 `feature:scan`；
- N1 路由仍由 app 持有，扫码路由由 app 接入 `feature:scan`。

## 3. MB-D-011 签收内容

### 3.1 真机最低标准

- 至少 **一台真实 Android 设备**；
- **API 26+**；推荐 **API 33+**；
- 模拟器、Robolectric、JVM 测试**不能替代**最终真机验证；
- 扫码/相机、SAF、备份恢复、权限与真实进程行为必须在真机上验证；
- 必须保留真机测试记录；记录缺失视为未验收。

### 3.2 测试记录字段

| 字段 | 要求 |
|---|---|
| 设备 | 厂商、型号、设备代号 |
| 系统 | Android 版本、API level、构建号 |
| 应用 | 提交完整哈希、APK 路径/哈希、版本号 |
| 用例 | 用例 ID、前置条件、步骤 |
| 结果 | 预期、实际、通过/失败 |
| 证据 | 日志、截图/录屏、必要时的 bug 链接 |
| 环境 | 日期时间、测试人、复核人 |
| 问题 | 失败复现步骤、严重级别、处置 |

记录归档在后续 Stage 5/6 的验收文档中；本记录不代替真机测试。

## 4. 一致性说明

### 4.1 与 MB-D-009（N1 五入口）

- N1 五入口顺序不变：酱汁 → 食材 → 菜谱 → 库存 → **扫码**；
- 扫码仍为底部第五入口，设置仍在顶栏；
- `feature:scan` 只承接扫码页面实现，不改变信息架构；
- 当前扫码仍为占位，未修改导航代码。

### 4.2 与 MB-D-003（13 模块为 Stage 1 目标）

- MB-D-003 的 13 模块是 **Stage 1–4 目标**，实际落地为 13；
- MB-D-004 是后续增量决策：Stage 5 起 14；
- 不得把 13 写成“历史错误”，也不得在 Stage 5 前把 14 写成“当前事实”；
- 当前 `settings.gradle.kts` 仍为 13，依赖检查期望值仍为 13。

### 4.3 与 MB-D-007（备份一致性）

- MB-D-007 已 `CLOSED`，备份/恢复实现已验收；
- 扫码模块不修改 `AutoBackupWorker`、`BackupArchiveWriter`、`RestoreExecutor`、写屏障或 WAL checkpoint；
- 扫码产生的食材/商品/库存数据仍走既有 Repository 与备份范围；
- 本次签收不改变 MB-D-007 的任何结论或保留项。
